**Scylax** is a light, non-intrusive, repeatable **Digital Attack Surface Cartography & Posture Assessment** pipeline built in pure Python 3.11+ (zero external `pip` dependencies). Designed for continuous threat exposure management (CTEM) and periodic security assessments, Scylax maps an organisation's external attack surface, identifies weak points, exposed services, associated CVEs / CISA KEVs, cloud perimeter assets, leaked credentials, and SaaS configuration weaknesses—without performing active exploitation or brute-force attacks.

> [!NOTE]
> The reports generated by Scylax (`report.html`, `report.md`, `findings_auto.tsv`) provide **raw evidence and candidate findings for human or AI validation and interpretation**, not a formal penetration testing report or definitive vulnerability conclusion.

It answers four questions every cycle:

1. **What does our perimeter look like from the internet today?** (Subdomains, IPs, ports, DNS/mail posture, Azure, GCP & AWS cloud assets, corporate emails)
2. **What is exposed that should not be?** (Management interfaces, API schemas, `.env`/`.git` leaks, permissive firewall rules / security groups, directory listings, leaked credentials in public breaches)
3. **What known vulnerabilities (CVEs / CISA KEVs) and potential entry points exist on live services?**
4. **What changed since the last run?** (New, resolved, and persisting findings)

## What it does and does not do

**Intrusiveness ceiling:** the opt-in content discovery (phase C) and its signature-confirmed path traversal check are the most aggressive things Scylax does. Every other check uses fixed, known paths and minimal reads (capped bytes, nothing stored). Scylax never fuzzes parameters, sends injection payloads, brute-forces credentials or probes for request smuggling, and checks that throttle (HTTP 429/503, timeouts) are slowed down and then abandoned per host. API keys are masked in every evidence file and warning.

**Does:**
- **Passive OSINT:** Subdomain enumeration (`subfinder`, `amass -passive`, `crt.sh`), DNS & mail posture (`SPF`, `DMARC`, `CAA`, `DNSSEC`, `AXFR`, wildcard, `WHOIS`), historical URLs (`Wayback CDX`), and `Shodan` lookups.
- **Leaked Passwords, Email Enumeration & Breach Intelligence (Phase 9):**
  - **Corporate Email Enumeration:** Discovers employee and corporate email addresses using `theHarvester`, `amass`, and `spiderfoot`, combined with passive sources (Ubuntu PGP keyserver queries, WHOIS registrant records, and historical Wayback CDX archives).
  - **HaveIBeenPwned (HIBP) Integration:** Audits corporate domains for data breach history through the public, keyless catalogue (`/api/v3/breaches?domain=...`). With an API key, checks discovered corporate accounts (`/api/v3/breachedaccount/...`).
  - **XposedOrNot Fallback:** Without an HIBP key, discovered accounts are checked against the free, keyless XposedOrNot API (about 1 request per second), and each breach name is enriched with HIBP's public breach metadata.
  - **Free Pwned Passwords API (k-Anonymity):** Validates passwords against HIBP's free, unauthenticated range API (`api.pwnedpasswords.com/range/{prefix}`) using SHA-1 prefix hashing to preserve privacy.
  - **Code Leak Detection:** Queries public GitHub repositories via `gh search code` and provides verified `trufflehog` recipes for local repository filesystems.
- **Automatic Subdomain -> IP Target Discovery:** Resolves all discovered subdomains, identifies hosting providers/ASNs, automatically filters out third-party CDNs/SaaS (`Cloudflare`, `Fastly`, `Akamai`, `HubSpot`, `GitHub`, etc.), and feeds organisation-owned IPs into active port/service scanning—while strictly isolating fragile `edge_ips` to slow banner fingerprinting.
- **Automated Service -> CVE & CISA KEV Correlation:** Extracts versioned CPEs from `nmap` XML and `Shodan`, queries **Shodan CVEDB** or, when `*.shodan.io` is unreachable, the keyless **NIST NVD API** (set `NVD_API_KEY` for higher rate limits), and flags services affected by high-severity CVEs or entries in the **CISA Known Exploited Vulnerabilities (KEV)** catalogue.
- **Web Surface & Potential Entry Point Detection:** Non-intrusive audit for exposed OpenAPI/Swagger schemas (`/swagger.json`, `/openapi.json`, `/v2/api-docs`, `/graphql`), Spring Boot Actuator, `.env`/`.git` exposures, CORS/cookie weaknesses, and historical parameter entry points (candidates for `IDOR/BOLA`, `LFI/Path Traversal`, `Open Redirect/SSRF`, and `SQLi` review).
- **Multi-Cloud Grey-Box Inventory:** Queries **Azure** (`az graph query`), **Google Cloud / GCP** (`gcloud`), and **Amazon Web Services / AWS** (`aws`) for static/ephemeral external IPs, Load Balancers, CloudFront, public RDS, and firewall rules / Security Groups open to `0.0.0.0/0`, followed by two-pass `nmap` verification. Cloud annexes are opt-in: A, G and W run only for providers configured in the scope (subscriptions, projects, profiles or an inventory file) or when named explicitly with `-p`; otherwise `az`/`gcloud`/`aws` are not even looked for.
- **Cloud Security Posture Management (CSPM, Optional via `--cloud-posture`):** Fast native configuration posture checks (plus optional deep CIS benchmark assessment via **Prowler** with `--prowler`):
  - **Azure:** Storage accounts (blob public access, HTTPS-only, minimum TLS 1.2), Key Vaults (purge protection), Azure SQL (public network access), Microsoft Defender for Cloud (Free tier vs Standard).
  - **GCP:** Cloud Storage (uniform bucket-level access, public `allUsers`/`allAuthenticatedUsers` IAM bindings), Cloud SQL (`0.0.0.0/0` authorized networks, SSL/TLS enforcement), IAM service accounts (default Compute Engine SA roles).
  - **AWS:** Root account MFA, IAM console user MFA, S3 buckets (Block Public Access, encryption), CloudTrail (multi-region trail, log file validation), SecurityHub & GuardDuty detector status, RDS (public accessibility, encryption at rest), EC2 EBS default encryption.
  - **Prowler:** Optional CIS benchmark compliance evaluation across Azure, GCP, or AWS when `--prowler` is supplied.
- **SaaS Security Posture Management (SSPM, Optional via `--saas-posture` or `saas_posture = true`):** Authenticated, read-only audit of organisation-owned SaaS tenant configurations (a separate category from unauthenticated external recon):
  - **Microsoft 365 / Entra ID:** Conditional Access policies (enforcement state, MFA for all users), Global Administrator MFA method registration, guest user volume and inactivity, stale user accounts (>90 days), high-risk OAuth permission grants consented to AllPrincipals (e.g. `Mail.ReadWrite`), app registration secret expiration, and tenant-wide MFA registration compliance.
  - **GitHub:** Organization 2FA enforcement and member compliance, default branch protection rules, open secret scanning alerts, and webhook SSL verification.
  - **Google Workspace:** Super admin MFA enforcement, third-party marketplace app permissions, external calendar sharing, and domain SPF/DKIM posture via `gam`.
- **Interactive HTML & Markdown Reporting:** Captures every executed command and output (`console/commands.jsonl`) and compiles `report.md` and `report.html` (including dedicated Cloud & SaaS Security Posture tables and CLI explorer).

**Does not, by design (Not an offensive exploiter or brute-forcer):**

| Never | How the pipeline enforces it |
|---|---|
| Exploitation, RCE, active injection | `nuclei` runs with `-exclude-tags intrusive,dos,fuzz,brute,default-login,xss,sqli,rce,lfi` and `-severity medium,high,critical` |
| Brute force, credential stuffing (`hydra`, etc.) | No credential testing tools or wordlists are included or supported |
| Heavy directory brute forcing | The phase 8 fallback checks a curated list of signed well-known paths; optional phase C content discovery is opt-in, rate-limited, owned-hosts only, and defaults to a small curated wordlist (point it at a larger one yourself) |
| DoS-rate traffic | `nmap --max-rate 400` (`40` for edge devices), `nuclei` and `httpx` capped at `50` req/s |
| Scanning third-party infrastructure | CDNs/SaaS and `exclude_ips` are automatically skipped; fragile `edge_ips` never receive full-range or `nuclei` scans |
| Downloading exposed files | Directory listings record filenames only; contents are never downloaded |
| Running without authorisation | Active phases refuse to start if `authorised_by` is empty and prompt for confirmation |

## Modular Plugin & Provider Architecture

Scylax decouples security tools, cloud providers, intelligence services, and container runners through a modular plugin architecture (`recon/plugins/`):

- **20 Built-in Plugins:**
  - **Network & Perimeter:** `nmap`, `dig`, `whois`
  - **Subdomain & DNS OSINT:** `subfinder`, `amass`, `dnsx`
  - **Web Surface & Fingerprinting:** `httpx`, `whatweb`, `nuclei`
  - **Leaked Credentials & Password Breach:** `theharvester`, `amass`, `spiderfoot`, `trufflehog`, `hibp`, `gh`
  - **Intelligence APIs:** `shodan` (host queries & CVEDB correlation), `hibp` (domain breaches, compromised accounts, and free k-anonymity password check)
  - **Cloud Infrastructure:** `az` (Azure), `gcloud` (GCP), `aws` (AWS), `prowler` (CIS benchmarks)
  - **SaaS Posture:** `m365_graph` (Microsoft 365 / Entra ID), `gh` (GitHub), `gam` (Google Workspace), `gitleaks` / `trufflehog` (secret scanning of public repos), `gobuster` (content discovery)
- **Plugin Lifecycle & Requirements:**
  Each phase explicitly declares its `required` and `optional` plugins (in `recon/deps.py`). If an optional plugin is missing, the phase runs in a graceful degraded mode using stdlib fallbacks or alternative tools.
- **Provider Transparency (`native` vs `docker`):**
  Plugins transparently run using either native binaries or containerized execution via `--docker`. When running via Docker, volume mounting (`-v <run_dir>:/data`) and argument path rewriting are handled automatically.

## Installation & Dependency Check

Scylax requires **Python 3.11+** (uses standard library `tomllib`, `urllib.request`, `xml.etree.ElementTree`, `venv`, etc. — zero external `pip` dependencies required).

### Automatic Virtual Environment Management (`.venv`)

To protect your host machine from environment pollution, Scylax automatically detects whether it is running within an active virtual environment:

- **Active venv:** Runs immediately without prompts.
- **Existing `.venv`:** If `.venv` already exists in the project root, Scylax seamlessly switches and re-execs using `.venv`'s Python interpreter.
- **No venv detected:**
  - Interactive mode prompts: `Create and switch to .venv now? [Y/n]`. Confirming creates `.venv` using the standard library `venv` module and relaunches the command inside it.
  - Non-interactive runs with `-y` / `--yes` create `.venv` automatically.
- **Bypass option (`--no-venv`):**
  When running inside pre-built Docker containers where dependencies are installed system-wide, pass `--no-venv` or export `NO_VENV=1` to bypass all virtual environment checks:
  ```bash
  ./scylax.py -s scopes/example.toml --no-venv
  ```

Check your whole setup at once with `--doctor` — Python, tools, your scope file,
which API-key integrations are active, your egress IP, and the command to run next:

```bash
./scylax.py --doctor -s scopes/<name>.toml
```

It exits `0` when nothing blocks a run and `1` when something must be fixed first
(missing required tool, or a scope that is absent or invalid). For the tool table
alone, use `--check-deps`; to validate a scope file alone, `--check-config`:

```bash
./scylax.py --check-deps
```

## Docker image (all dependencies included)

`--docker` still needs the tools' images and a Docker daemon at run time. The repository's `Dockerfile` instead builds **one self-contained image** with Scylax and every tool installed natively, so a run needs nothing on the host but Docker:

| Target | Contents |
|---|---|
| `core` | Python 3.12, `nmap`, `dig`, `whois`, `whatweb`, `subfinder`, `dnsx`, `httpx`, `nuclei` (templates baked in), `amass` v4, `trufflehog`, `gitleaks`, `gobuster`, `theHarvester`, `spiderfoot` |
| `full` (default) | `core` + `az` (with `resource-graph`), `gcloud`, `aws` v2, `gh`, `prowler` |

```bash
docker build -t scylax .                         # full
docker build -t scylax:core --target core .      # lighter, no cloud/SaaS CLIs
```

Scylax reads `scopes/` and writes `runs/` relative to the working directory, which in the image is `/work`. Mount the folder that holds them (keep real scopes and evidence outside this repository):

```bash
cd ~/assessments                                 # contains scopes/ and runs/
docker run --rm -it -v "$PWD:/work" \
  -e SHODAN_API_KEY -e HIBP_API_KEY \
  scylax -s scopes/acme.toml -qq -y
```

For the cloud and SaaS annexes, mount the CLI credentials read-only and pass the SaaS variables:

```bash
docker run --rm -it -v "$PWD:/work" \
  -v ~/.azure:/root/.azure -v ~/.aws:/root/.aws:ro \
  -v ~/.config/gcloud:/root/.config/gcloud:ro -v ~/.config/gh:/root/.config/gh:ro \
  -e M365_TENANT_ID -e M365_CLIENT_ID -e M365_CLIENT_SECRET -e GITHUB_ORG \
  scylax -s scopes/acme.toml -p "A G W S T" --cloud-posture
```

Notes:
- **Do not pass `-D`/`--docker` inside the image**: every tool is already native.
- The container runs as root so phase 4 can run the UDP scan of VPN ports (it needs raw sockets). Docker's default capabilities are enough; no `--privileged`. On Linux hosts, `runs/` files will be owned by root unless you add `--user "$(id -u):$(id -g)"` (that skips the UDP scan).
- `~/.azure` is mounted read-write because `az` refreshes its token cache there.
- Refresh the nuclei templates without rebuilding: `docker run --rm --entrypoint nuclei scylax -update-templates` only updates that container; rebuild the image (or mount a volume at `/root/nuclei-templates`) to keep them.
- Tool versions are build arguments (`SUBFINDER_VERSION`, `DNSX_VERSION`, `HTTPX_VERSION`, `NUCLEI_VERSION`, `AMASS_VERSION`, `TRUFFLEHOG_VERSION`, `THEHARVESTER_REF`, `SPIDERFOOT_REF`); pin them for reproducible builds.
- GAM (Google Workspace posture) is not included: its installer is interactive. Run the Google Workspace checks from a host with GAM installed.

## Scope configuration (`.toml`)

Copy the template and edit it for your organisation:

```bash
cp scopes/example.toml scopes/acme.toml
```

Key settings in `scopes/example.toml`:

| Section / Key | Required | Meaning |
|---|---|---|
| `[engagement] engagement` | yes | Assessment name displayed in `report.html` and `report.md` |
| `[engagement] authorised_by`, `authorisation_ref` | for active phases | Name/date and ticket reference of written authorisation |
| `[targets] domains` | yes | List of root domains you own (e.g. `["example.com", "example.io"]`) |
| `[targets] auto_discover_targets` | optional (`true`) | Automatically port-scan IPs resolved from discovered subdomains (after filtering out CDNs/SaaS, `edge_ips`, and `exclude_ips`) |
| `[targets] skip_portscan_orgs` | optional | List of CDN/SaaS providers skipped during target IP auto-discovery |
| `[targets] hvt_ips` | optional | Additional high-value own IPs to always include in Phase 4 & Phase 8 |
| `[targets] edge_ips`, `edge_ports` | optional | Fragile edge devices (routers, branch firewalls): isolated to slow banner fingerprinting in Phase `4b` |
| `[targets] exclude_ips` | optional | Never touched actively |
| `[targets] owned_ranges`, `owned_ips_file` | recommended | Ownership allowlist: auto-discovered IPs outside it (CDN, SaaS, shared cloud) are never port-scanned or nuclei-scanned; see `osint/skipped_targets.tsv` |
| `[azure] azure_subscriptions`, `azure_inventory_file` | optional | Enable Annex A for these Azure subscriptions or a static TSV file (unset: A is skipped unless named with `-p`) |
| `[gcp] gcp_projects`, `gcp_inventory_file` | optional | Enable Annex G for these GCP project IDs or a static TSV file (unset: G is skipped unless named with `-p`) |
| `[aws] aws_profiles`, `aws_regions`, `aws_inventory_file` | optional | Enable Annex W for these AWS CLI profiles/regions or a static TSV file (unset: W is skipped unless named with `-p`) |
| `[cloud_posture] cloud_posture`, `use_prowler` | optional | Enable cloud configuration posture checks and optional Prowler CIS scans |
| `[intelligence] shodan_api_key`, `hibp_api_key` | optional | Optional API keys for Shodan host lookups and HaveIBeenPwned domain breach auditing |
| `[saas] saas_posture`, `providers` | optional | Enable authenticated read-only SaaS configuration posture checks across `["m365", "github", "google"]` (disabled by default) |
| `[thresholds] min_apache`, `min_nginx`, `min_routeros` | optional | Minimum version floors used by Phase T triage |

## Running it

```text
./scylax.py -s SCOPE_FILE [--profile NAME] [-p "PHASES"] [-d DATE] [-P] [-q | -qq] [-n] [-y] [-D] [--no-venv] [--cloud-posture] [--saas-posture] [--prowler] [--doctor] [--check-deps] [--check-config] [--report-only DIR] [--report-from-bundle FILE] [--export DIR]
```

| Option | Meaning |
|---|---|
| `-s`, `--scope FILE` | Scope `.toml` file (default: `$SCOPE` or `scopes/default.toml`) |
| `--profile NAME` | Phase-group preset that sets the phases and posture toggles (or `$PROFILE`). See [Profiles](#profiles---profile). An explicit `-p` overrides the phases. `--profile list` prints them all |
| `-p`, `--phases "PHASES"` | Phases to run, space-separated (default: `"1 2 3 4 4b 5 6 7 8 9 A G W S T"`) |
| `-d`, `--date DATE` | Run folder date (default: today `YYYY-MM-DD`). Reuse to resume or re-triage |
| `-P`, `--passive-only` | Passive phases only (skips active scanning `3, 4, 4b, 5, 8, A, G, W`; does not skip S) |
| `-n`, `--no-cloud` | Skip cloud annexes (`A`, `G`, and `W`) |
| `--no-venv` | Do not prompt for or use a virtual environment (or `NO_VENV=1`) |
| `--cloud-posture` | Enable cloud security posture checks across Azure, GCP, and AWS (or `CLOUD_POSTURE=1`) |
| `--saas-posture` | Enable SaaS security posture checks across M365, GitHub, and Google Workspace (or `SAAS_POSTURE=1`) |
| `--prowler` | Enable deep Prowler CSPM assessment during cloud posture checks (or `USE_PROWLER=1`) |
| `--shodan-key KEY` | Shodan API key for phase 7 host lookups (or `SHODAN_API_KEY`) |
| `--hibp-key KEY` | HaveIBeenPwned API key for domain/account breach audit (or `HIBP_API_KEY`) |
| `-q`, `--quick` | Quick port scan in Phase 4: `-q` scans the top 1,000 ports and `-qq` the top 100, instead of all 65,535 (or `QUICK=1` / `QUICK=2`). `--top-ports` takes precedence |
| `--top-ports N` | Specific number of top ports to scan with Nmap (e.g. `100`, `1000`) |
| `-y`, `--yes` | Skip interactive confirmation prompt before active phases (or `YES=1`) |
| `--authorised-by NAME` | Written authorisation name/role for active phases (or `AUTHORISED_BY`) |
| `--authorisation-ref REF` | Written authorisation ticket/ref for active phases (or `AUTHORISATION_REF`) |
| `-D`, `--docker` | Run supported tools via Docker containers instead of native binaries |
| `--dry-run` | List the commands and HTTP requests each phase would issue, run nothing and write no evidence. Commands that depend on earlier phases' results, and requests that are only made after a first response qualifies, cannot be listed |
| `--resume` | Skip phases already completed (with no tool failure) in this run folder, and inside a phase that was interrupted or had failures skip the units already finished (per IP nmap pass, nuclei batch, edge device, cloud IP, breach-lookup account, Shodan IP, content-discovery host); console evidence of the unfinished phase is kept. Editing the scope file invalidates both. `gaps.txt` is kept, so gaps accumulate. Without `--resume` everything runs fresh |
| `--jobs N` | Run up to N independent phases concurrently (default `1`; or `SCYLAX_JOBS`, or scope `jobs`). Only passive/API/offline phases overlap: phases that send traffic to the targets still run one at a time, so the traffic intensity is unchanged |
| `--doctor` | One-shot health check (Python, tools, scope, API keys, egress IP, next command) and exit; `0` if nothing blocks a run, `1` otherwise |
| `--check-deps` | Print dependency status table and exit |
| `--check-config` | Validate the scope file (unknown keys, missing files, empty sections) and exit |
| `--report-only DIR` | Regenerate `report.md` and `report.html` for an existing run folder |
| `--report-from-bundle FILE` | Rebuild `report.md` and `report.html` from an `ai_bundle.md` alone |
| `--export DIR` | Write `report_data.json` (consolidated assets + findings + relations) for an existing run and exit |

### Profiles (`--profile`)

Instead of listing phases by hand, pick a **profile** — a named phase group that
also sets the right posture toggles. An explicit `-p` still wins; `--profile list`
prints them all.

```bash
./scylax.py -s scopes/acme.toml --profile light       # safe active recon, no port scans
./scylax.py -s scopes/acme.toml --profile external    # full external attack surface
./scylax.py -s scopes/acme.toml --profile blueteam    # posture of your own cloud/SaaS
```

| Profile | Phases | Toggles | For |
|---|---|---|---|
| `passive` | `1 2 6 7 9` | — | Zero-touch OSINT (no authorisation needed) |
| `light` | `1 2 3 5 6 7 8 9 E` | — | Safe active recon, no nmap port scans |
| `external` *(alias `redteam`)* | `1 2 3 4 4b 5 6 7 8 9 C E` | — | Full external attack surface |
| `blueteam` | `1 2 6 7 9 E A G W S` | cloud + SaaS posture | Defender posture of your own tenants |
| `purpleteam` | `1 2 3 4 4b 5 6 7 8 9 A G W C E S` | cloud + SaaS posture | Offense + defense, full picture |
| `full` | all phases | cloud + SaaS posture + Prowler | Maximum coverage |
| `web` | `2 3 5 6 8 C` | — | Web-facing surface only |
| `cloud` | `A G W` | cloud posture | Cloud annexes only |
| `intel` *(alias `leaks`)* | `6 7 9` | — | Historical URLs, CVE, breaches, secret leaks |
| `saas` | `E S` | SaaS posture | Anonymous exposure + authenticated SaaS posture |

Phase `T` (triage/report) is always appended. Profiles treat their opt-in phases
(cloud `A/G/W`, content `C`, SaaS exposure `E`) as explicitly requested, so they
run even without provider config — `blueteam`, for example, queries the active
Azure tenant. Aliases: `osint→passive`, `redteam/attacker→external`, `leaks→intel`.

### Typical workflow

1. **Check your setup** (tools, scope, keys, egress, next step):
   ```bash
   ./scylax.py --doctor -s scopes/acme.toml
   ```

2. **Passive discovery first** (DNS, WHOIS, CT logs, Wayback, Shodan, target IP auto-discovery):
   ```bash
   ./scylax.py -s scopes/acme.toml -P
   ```

3. **Review discovered assets** in `runs/acme/<date>/osint/discovered_targets.txt` and `osint/ip_orgs.tsv` to confirm if any fragile office router IP should be moved to `edge_ips`.

4. **Run active & cloud phases, followed by triage and report generation:**
   ```bash
   ./scylax.py -s scopes/acme.toml -p "3 4 4b 5 7 8 A G W T" --cloud-posture
   ```

5. **Open the interactive report:**
   ```bash
   open runs/acme/<date>/report.html
   ```

## Phases in detail

| # | Phase | What it does | Tools | Mode |
|---|---|---|---|---|
| `1` | Subdomain enumeration | Passive enumeration from CT logs and OSINT sources; diff vs previous run | `subfinder`, `amass -passive`, `crt.sh` | Passive |
| `2` | DNS posture & IP auto-discovery | Resolves all subdomains; checks NS, MX, SPF, DMARC, CAA, DNSKEY, AXFR, wildcard, WHOIS, apex ownership; classifies IP ASNs and auto-discovers non-CDN target IPs | `dnsx`, `dig`, `whois` | Passive |
| `3` | Live web hosts & entry surface | Probes resolving hosts; detects directory listings; checks well-known API/config paths (`Swagger/OpenAPI`, `Actuator`, `.env`, `.git`) and CORS/cookie hygiene | `httpx` (or native fallback) | Active (light) |
| `4` | HVT & discovered IP scan | Two-pass scan on `hvt_ips` + `discovered_targets.txt` (strictly excluding `edge_ips` and `exclude_ips`): full TCP port discovery followed by `-sV` with safe NSE scripts | `nmap` | Active |
| `4b` | Edge device fingerprint | Slow, safe banner fingerprint (`-T2 --max-rate 40 -sV --script banner`) on `edge_ips` and `edge_ports` only | `nmap` | Active (light) |
| `5` | Technology fingerprint | Extracts technology stack from `httpx` and single-request `whatweb -a 1` | `httpx`, `whatweb` | Active (light) |
| `6` | Historical URLs & entry points | Queries Wayback CDX; filters sensitive/critical file extensions and classifies parameter entry points (`IDOR`, `LFI`, `Open Redirect`, `SQLi` candidates) | Wayback CDX | Passive |
| `7` | Shodan + CVE / CISA KEV correlation | Queries Shodan host API (if key set) and correlates Nmap XML CPEs/versions against Shodan CVEDB for CVSS scores and **CISA KEV** status | Shodan API & CVEDB | Passive |
| `8` | Vulnerability detection | Runs non-intrusive `nuclei` templates (`medium,high,critical`) against live web hosts and HVTs (`edge_ips` excluded) | `nuclei` | Active (light) |
| `9` | Leaked credentials & breach detection | Enumerates corporate emails (`theharvester`, `amass`, `spiderfoot`, PGP/WHOIS/Wayback) and correlates against HaveIBeenPwned for domain & compromised account breaches; scans the org's public repos for leaked secrets (`gitleaks`/`trufflehog`) | `theharvester` (req), `amass`, `spiderfoot`, `hibp`, `gitleaks`, `trufflehog`, `gh` | Passive / Intelligence |
| `A` | Azure annex (grey-box) | Inventories all public IPs and Internet-facing NSG rules via Azure Resource Graph, followed by two-pass `nmap` scan (and optional posture checks) | `az`, `nmap` | Active |
| `G` | Google Cloud annex (grey-box) | Inventories static/ephemeral VM IPs, forwarding rules, and `0.0.0.0/0` VPC firewall rules across GCP projects, followed by two-pass `nmap` scan (and optional posture checks) | `gcloud`, `nmap` | Active |
| `W` | AWS annex (grey-box) | Inventories Elastic IPs, EC2 public IPs, ALBs, public RDS, and Internet-facing Security Groups across regions and profiles, followed by two-pass `nmap` scan (and optional posture checks) | `aws`, `nmap` | Active |
| `C` | Content discovery (optional) | Opt-in active check for exposed control panels, API docs, source/config, backups and telemetry on owned hosts, plus signature-confirmed path traversal; gobuster or a native probe | `gobuster` | Active (opt-in) |
| `E` | Third-party SaaS exposure (optional) | Opt-in. Fixed, anonymous, read-only requests to `<org>.atlassian.net` (Jira / Confluence Cloud) testing whether issues, projects, users, dashboards, spaces or pages answer without login. Only counts are kept, never record contents. With `use_misconfig_mapper = true` it also runs `misconfig-mapper` on the same exact names (no permutations, delayed, plain-GET templates only) | native HTTP; optional `misconfig-mapper` | Active (opt-in) |
| `S` | SaaS security posture | Authenticated read-only configuration audit of M365/Entra ID, GitHub org, and Google Workspace tenants | Graph API, `gh`, `gam` | Authenticated Audit |
| `T` | Triage, Diff & Reporting | Evaluates all outputs to produce `findings_auto.md/.tsv`, `diff.md`, `report.md`, and the interactive tabbed `report.html` | Python stdlib | Offline |

## Monthly runs (CTEM)

- Use a fresh `runs/<scope>/<date>/` per run so `diff.md` and `findings_history.json` have a baseline.
- Record accepted risks / false positives in `scopes/<scope>.suppressions.toml` (owner, reason, expiry; see `scopes/example.suppressions.toml` and [docs/configuration.md](docs/configuration.md#finding-suppressions-suppressionstoml)) so they stop showing as new each month without disappearing.
- Set `owned_ips_file` (e.g. the Azure public-IP export) so CDN/SaaS/shared-cloud IPs are never port-scanned.
- Prefer a full run (no `-q`/`-qq`) once a month; quick modes are for ad-hoc checks.
- Export `NVD_API_KEY` when `*.shodan.io` is blocked: CVE correlation then uses NVD at ~10x the keyless rate.
- Data probes read at most 4 KB per URL (header row / schema) and never download datasets; the full size is taken from `Content-Range` / `Content-Length`.
